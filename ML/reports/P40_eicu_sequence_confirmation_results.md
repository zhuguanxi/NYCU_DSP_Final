# P40 完整 eICU 驗證入口與 Demo 試跑

依 [P40 規格](P40_eicu_sequence_confirmation_protocol.md)，將 P38 加入 [P29](P29_eicu_ensemble_confirmation_protocol.md) 的同隊列評估。P28 對原凍結 Elastic 為主要比較。P38 對 P28 及原凍結 Elastic 為次要比較。所有模型共用患者、尿量 mL 對齊、48 小時輸入窗與住院死亡結局。

## CPU 試跑

使用原 eICU Demo 的全部合格病例，共 782 次 stay、719 人、91 次住院死亡。兩種取樣在 P28、P38 和原凍結 Elastic 的 AP、AUROC、Brier 和 0.5 門檻敏感度，均與既有凍結評估逐值相同。P38 的兩組配對區間也完整重現。模型擬合 0 次。

| 取樣 | 凍結 Elastic AP | P28 AP | P38 AP | P38 對 P28 AP 差及 95% 區間 |
| --- | ---: | ---: | ---: | --- |
| 整點 | 0.48957 | 0.50144 | 0.50356 | +0.00211 [−0.01970, +0.02448] |
| 原始間隔 | 0.47724 | 0.49916 | 0.49707 | −0.00210 [−0.02490, +0.02299] |

整點主要比較 P28 減凍結 Elastic 的 AP 差為 +0.01188，95% 區間 [−0.03739, +0.05706]。P38 減凍結 Elastic 的 AP 差為 +0.01399，區間 [−0.04019, +0.06320]。這些區間重現既有 Demo 探索結果。

## 患者排除與正式執行

流程將排除參照的患者表與 P28 評估時的 SHA-256 比對，並在評估後複核。同時記錄原始輸入、模型和參照的雜湊。用合成病例驗證，屬於同一 Demo 患者的其他 ICU stay 也會被排除，識別鍵衝突或更換參照時會停止。也測過把本機 Demo 路徑傳入正式模式，程式會拒絕。

本機只有 eICU Demo，正式比較待有授權的 eICU v2.0。依 [P40 的 CPU 執行方式](P40_eicu_sequence_confirmation_protocol.md)，指定完整資料目錄即可對不重疊的獨立患者評估。在 Git 排除目錄 `artifacts/p40_demo_smoke/` 保存本次彙總。
