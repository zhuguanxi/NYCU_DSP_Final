## 優先順序

1. **乳酸**。eICU 有 233/782 筆 stay 看得到乳酸，兩個 MA-GBT 都有 27.11% 的預測直接用到補值乳酸。相較 GCS，乳酸全遮的 Set C AP 變化很小，Full 為 −0.0046，Elastic 為 +0.0034。覆蓋率匹配時兩組都小幅下降。這支持先檢查乳酸增強能否降低外部補值依賴，AP 要另行驗證。
2. **GCS**。Set C 在全遮及匹配遮蔽時，兩個模型家族的 AP 降幅都最大。若以 Set C 遮蔽 AP 為主，GCS 仍是最重要的欄位。下一輪比較乳酸時保留 GCS 全遮與未遮蔽 AP 作為對照。
3. **機械通氣量測次數**。MA-GBT 單欄全遮 AP 的第二大降幅是這一欄。兩組各有四個分裂使用機械通氣量測次數，原 eICU 對齊把該欄設為未觀測且次數為 0。這個結果指向量測狀態與欄位對齊，和直接使用補值統計量是兩種情況。

膽紅素、HCO₃ 和 BUN 沒有 P9 的單欄遮蔽可供排名。eICU 的補值路徑比例和 Set C 遮蔽 AP 差衡量不同現象，不能用一個數字推算另一個。

## 重跑

在 `ML` 執行，依序使用原 GCS-only 環境與 P13 的 CPU 環境。MA-GBT 使用作者的路徑依賴函式並逐欄限制缺失矩陣。GCS-only 透過原生葉節點回溯實際路徑。兩組使用已凍結模型、補值與資料列。

```powershell
$maRuntime = Join-Path (Get-Location) 'artifacts\ma_gbt_runtime'
$env:PYTHONPATH = Join-Path $maRuntime 'upstream'
$env:CUDA_VISIBLE_DEVICES = '-1'
$env:PYTHONDONTWRITEBYTECODE = '1'
& .\.venv\Scripts\python.exe src/audit_ma_gbt_missingness.py gcs
& (Join-Path $maRuntime '.venv\Scripts\python.exe') src/audit_ma_gbt_missingness.py ma
```

完整彙總及來源雜湊保存在 Git 排除的 `ML/artifacts/ma_gbt_imputed_path_audit/`。兩個輸出檔的 Set C 數字和 P16 來源雜湊一致。重跑前先保留既有輸出。
