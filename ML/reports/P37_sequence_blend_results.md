# P37 序列加權的分數修正幅度

## P12 A/B 選型

依 [P37 規格](P37_sequence_blend_protocol.md)，用 CPU 重現逐小時與四小時網路各三折，並逐值核對 P28、P33、P34 的 P35 折外 AP。58 個新規則與兩個既有配置中，39 個通過原未遮蔽與 GCS 全遮門檻。

選定四小時序列，將它與 P28 的對數勝算差截在 ±2，乘以 25% 後加回 P28。在轉回機率前，這將加到 P28 的對數勝算修正限制在 ±0.5。A/B 加權 AP 比原 P34 增加 0.00055，比只改機率權重的最佳組高 0.00031。既有模型與輸入雜湊皆已核對，沒有重新擬合最終模型。

| 配置 | 未遮蔽 AP | GCS 全遮 AP | 原跨庫模擬 AP | 尿量部分恢復 AP | 觀測分布模擬 AP | 加權 AP |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| P28 | 0.56072 | 0.51061 | 0.52244 | 0.53415 | 0.53415 | 0.53875 |
| P33 逐小時，25% 機率 | 0.56747 | 0.51375 | 0.52825 | 0.53940 | 0.53473 | 0.54309 |
| P34 四小時，25% 機率 | 0.56755 | 0.51505 | 0.52938 | 0.53929 | 0.53624 | 0.54379 |

| P37 四小時，25% 對數勝算，差限 ±2 | 0.56797 | 0.51537 | 0.52997 | 0.53976 | 0.53716 | 0.54435 |

兩個觀測分布模擬沿用 P35 的 eICU 量測小時直方圖，只有序列輸入被擾動，P28 分數仍固定。選型的死亡標籤全來自 A/B。

在尿量 mL 對齊的整點設定，P37 相對 P28 的 AP 差為 −0.01178，95% 區間為 [−0.03483, +0.01180]。相對凍結 Elastic 增加約 0.00010，區間 [−0.05377, +0.05240]。P37 的 AUROC 為 0.82723、Brier 為 0.08043，0.5 門檻敏感度為 12.09%。

P37 在 Set C 的 14 個情境相對 P34 都有 AP 點估計增益。Set C 未遮蔽和 Demo 四種設定相對 P34 的區間均包含零。P28 維持 Demo 四種設定的最高 AP，依 [P29 規格](P29_eicu_ensemble_confirmation_protocol.md) 保留作獨立確認。Set C 與 Demo 已多次用於探索性比較，仍需用與 Demo 患者不重疊的完整 eICU 驗證外部增益。

用 [P33 的 Torch CPU 環境](P33_hourly_sequence_protocol.md) 跑完選型後，在 `ML` 恢復 [P21 的 CPU 環境](P21_predictive_boosting_protocol.md)，執行 `& $py src/evaluate_hourly_sequence.py --blend`。模型、完整配對彙總、來源雜湊與選型保留在 Git 排除目錄 `artifacts/p37_sequence_blend/` 及既有 P28、P33、P34 產物目錄。
