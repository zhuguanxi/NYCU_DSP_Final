# P37 限制序列分數修正幅度

前兩輪的量測門檻和觀測分布增強都保留 P34。這輪檢查逐小時或四小時序列分數只小幅修正 P28 時，是否能維持排序增益。沿用 48 小時窗、住院死亡、原 A/B 三折與 CPU。

- 比較機率加權與對數勝算加權。機率加權使用序列權重 5%、10%、15%、20%、25%、40%。對數勝算加權先算序列與 P28 的對數勝算差，再將差限制在正負 0.5、1、2，或不限制，乘上相同六種權重後加回 P28 的對數勝算。轉換前將機率限制在 `[10⁻⁷, 1−10⁻⁷]`。這是排序分數的組合規則。
- P33、P34 固定 25% 機率加權納入選型，P28 供對照。先重現 P35 已存的三組折外評估。沿用原觀測分布的兩組額外模擬，這兩組只有序列輸入改變。標籤只取自 A/B。
- 候選相對 P33 的未遮蔽 AP 和 GCS 全遮 AP 最多各降 0.003、0.005。通過者先按 P35 的加權 AP 選，其次以未遮蔽 AP 決定同分。權重依序是未遮蔽 35%、原跨庫模擬 10%、尿量部分恢復 15%、GCS 全遮 15%、兩組觀測分布模擬平均 25%。
- 選中新的組合規則時，直接使用原凍結的序列與 P28 模型，以原 Set C、eICU Demo 設定比較。原固定配置保留時沿用其凍結評估。三折只重現原網路，沒有新的全 A/B 擬合。

在 `ML` 內使用 [P33 的 CPU 環境](P33_hourly_sequence_protocol.md) 與 [P35 的分布資料](P35_sequence_gate_protocol.md)，執行 `src/select_sequence_blend.py`。候選彙總保留於 Git 排除的 `artifacts/p37_sequence_blend/selection.json`。
