# P34 固定四小時表示與量測時間壓力規格

P33 逐小時分支提高 Set C AP，eICU Demo 點估計較低。P34 保留原 48 小時窗、住院死亡定義、20 個通道與 P33 網路，每四小時將已觀測的小時值取中位數，放在固定區塊尾端。空區塊保留缺失。這樣同區塊內的量測頻率差異不會直接增加模型的觀測位置數。量測時間與數量可各自影響模型，見 [Nestor 等](https://proceedings.mlr.press/v106/nestor19a.html) 及 [Pike 預印本](https://arxiv.org/abs/2610.42126)。

## A/B 選擇

- 逐值重現 P33 在原三折的選定混合結果。粗時間區塊網路比較原資料訓練及帶缺失增強的訓練，各取 8、16 回合。增強從 P26 的固定跨庫模擬副本開始，其中一半住院序列在各有資料的通道隨機保留一半觀測小時，向上取整，另一半移除末 12 小時。原資料與副本的損失權重為 0.75／0.25。
- 驗證沿用 P33 的六個版本，另外選同一組固定的尿量部分恢復模擬，生成隨機保留約一半、末 12 小時全遮、及與末 12 小時遮蔽逐 stay 逐通道同數量的隨機保留。三個畫面只擾動序列成分，P28 的表格分數固定，以測序列成分的敏感度。這些畫面與完整管線的實際缺失不同。
- P34 一次只把一個四小時表示模型混入 P28，機率權重為 0.10、0.15、0.25、0.50 或 1。以既定 P33 作門檻參照，未遮蔽 AP 至多降 0.003、GCS 全遮 AP 至多降 0.005。將通過門檻者與 P33 比較，權重分別為未遮蔽 0.35、原跨庫模擬 0.10、尿量部分恢復模擬 0.15、GCS 全遮 0.15、三個時間擾動畫面的平均 0.25。同分取較高未遮蔽 AP。
- 如 P34 入選，就以全 A/B 擬合一次並凍結，沿用 P33 的 Set C 與 eICU Demo 評估。若保留 P33，沿用其既有評估。完整 eICU 仍依 P29 既定規格。

全程 CPU。沿用 [P33 環境](P33_hourly_sequence_protocol.md) 的 P13 CPU PyTorch 與 P33 局部套件，在 `ML` 執行 `& .\artifacts\ma_gbt_runtime\.venv\Scripts\python.exe src/train_sequence_cadence.py`。選型彙總和模型位於 Git 排除的 `ML/artifacts/p34_sequence_cadence/`。

如選出四小時表示，恢復 P21 主環境，再用 `& $py src/evaluate_hourly_sequence.py --cadence` 比較 P28、P33 和 P34。凍結的 P33 會在同一隊列重現，再計算 P34 的配對 AP 和 AUROC 差。
