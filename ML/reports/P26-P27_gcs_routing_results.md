## A/B 選擇

依 [P26 規格](P26_gcs_routed_temporal_protocol.md)，固定原三折、48 小時窗和標籤，以 CPU 比較 49 個配置，其中 24 個通過兩個 AP 門檻。選出 P22 時間窗 XGBoost 作一般模型。當 GCS 量測次數為零，分數完全由訓練時全程遮蔽 GCS 的 LightGBM 產生。A/B 的 P22 未遮蔽、原跨資料集模擬與 GCS 全遮 AP 均逐值重現，最終配置在 Set C 與 eICU Demo 評估前凍結。

## P27 完整 eICU 評估流程試跑

依 [P27 規格](P27_eicu_confirmation_protocol.md)，以 CPU 在 Demo 固定抽取 120 人、129 次 stay、7 次住院死亡，完成原始表分批抽取、隊列重建、尿量對齊、兩種取樣、三個凍結模型與配對區間計算，重訓 0 次。尿量對齊涵蓋 85 次 stay。另用 Demo 核對 2,520 組 stay 鍵和 1,841 個患者鍵，確認程式拒絕患者完全重疊的隊列。

本機只有 Demo，獨立患者隊列仍待取得並核對 [PhysioNet 完整版](https://physionet.org/content/eicu-crd/2.0/)。Demo 產物標記為 `demo_runtime_test`。個案資料、模型、折外預測及運行彙總保留在 Git 排除的本機目錄。P26 詳細數據在 `ML/artifacts/p26_gcs_routed_temporal/evaluation/`，P27 試跑在 `ML/artifacts/p27_demo_smoke/`。
